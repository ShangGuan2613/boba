Boba · Lesson 06

监控录像：出了事，能倒带回放

trace 记录“到底发生了什么”，eval 证明“修好之后没有再坏”。

约 14 分钟 · 前置 Lesson 05 · trace 速查 · Harness 地图

1. 没有监控录像，只能靠猜

打烊对账，少了 80 元。店长问前台，前台说：“我按流程点了。”问后厨，后厨说：“我没接到那单。”

两个人都不像在撒谎。但没有监控，店长只能猜：是前台漏点？后厨漏做？还是顾客没付？

Agent 也一样。循环跑完只留下一句“失败了”，你无法知道是模型没调工具、工具报错、护栏拒绝，还是预算到点。没有 trace 的运行，等于没有监控录像的店。

2. trace 是什么：一行一件事

监控录像不写“今天不太对”，它按时间记录每一帧。trace 也按顺序记录每一个事件，一行一条，只追加、不改写。

字段 回答什么问题 例子
seq 这是第几件事？ 1, 2, 3 ...
ts 什么时候发生的？ 1763... .42
run_id 属于哪一次运行？ run_20261119_001
type 发生了什么类型的事？ tool.call
data 细节是什么？ {"tool": "order_create", "quantity": 10}

格式用 JSONL：一行一个 JSON。好处很土但很实用——能直接 grep、能按 run_id 过滤、能原样回放。

{"seq": 1, "ts": 1.0, "run_id": "run_1", "type": "run.start", "data": {"user": "3 号桌要 20 杯"}}
{"seq": 2, "ts": 1.1, "run_id": "run_1", "type": "model.turn", "data": {"text": "拆成两单"}}
{"seq": 3, "ts": 1.2, "run_id": "run_1", "type": "tool.call", "data": {"tool": "order_create", "quantity": 10}}

3. 四种录像，能回答什么

点标签，看同一套事件格式怎么记录不同的事故。注意最后一种：没有 run.end 的 trace。

正常一单：从头到尾有收尾

seq 1  run.start          user="3 号桌要 5 杯"
seq 2  model.turn         text="下一单"
seq 3  tool.call          tool="order_create", quantity=5
seq 4  tool.result        is_error=false
seq 5  state.write        total_cups=5
seq 6  run.end            status="ok"

能回答：谁点的、调了什么、成没成、状态写没写、最后是不是正常结束。

拆单被拒：拒绝也有记录

seq 1  run.start          user="3 号桌要 20 杯"
seq 2  model.turn         text="拆成两单"
seq 3  tool.call          tool="order_create", quantity=10
seq 4  tool.result        is_error=false
seq 5  state.write        total_cups=10
seq 6  tool.call          tool="order_create", quantity=10
seq 7  guardrail.denied   code="permission_denied"
seq 8  tool.result        is_error=true
seq 9  run.end            status="permission_denied"

能回答：不是“工具坏了”，是第二单被 session 级护栏拦下；第一单已经成功，状态停在 10 杯。

预算超时：时间去哪了

seq 1  run.start
seq 2  model.turn
seq 3  tool.call          tool="inventory_check"
seq 4  tool.result        is_error=true, code="tool_failed"
seq 5  model.turn
seq 6  tool.call          tool="inventory_check"
seq 7  tool.result        is_error=true, code="tool_failed"
seq 8  run.end            status="timeout"

能回答：模型在重试同一个失败工具；超时不是模型“笨”，是循环没有在失败后换策略。预算和 trace 一起看，才知道该改哪。

没写完的录像：没有 run.end

seq 1  run.start
seq 2  model.turn
seq 3  tool.call          tool="order_create", quantity=10
seq 4  tool.result        is_error=false
（没有 seq 5）

能回答：这次运行没有正常收尾。可能进程崩了、机器重启了，或者停止路径漏了 run.end。status() 会返回 incomplete，这本身就是信号。

4. 代码：只追加，不改写

Trace.emit 只做一件事：给事件编号、打时间戳、塞进列表。没有复杂逻辑，才不容易把观测代码本身写出 bug。

@dataclass(frozen=True)
class TraceEvent:
    seq: int
    ts: float
    run_id: str
    type: str
    data: dict

class Trace:
    def __init__(self, run_id, clock=time.time):
        self.run_id = run_id
        self._clock = clock
        self.events = []

    def emit(self, event_type, **data):
        event = TraceEvent(
            seq=len(self.events) + 1,
            ts=self._clock(),
            run_id=self.run_id,
            type=event_type,
            data=data,
        )
        self.events.append(event)
        return event

落盘用 JSONL；读回来时保持原来的顺序：

def to_jsonl(self):
    return "\n".join(
        json.dumps(asdict(e), ensure_ascii=False)
        for e in self.events
    )

@classmethod
def from_jsonl(cls, text):
    events = [
        TraceEvent(**json.loads(line))
        for line in text.splitlines()
        if line.strip()
    ]
    trace = cls(events[0].run_id if events else "")
    trace.events = events
    return trace

收尾状态只看最后一条 run.end。没有它，就说明这次运行没写完：

def status(self):
    for event in reversed(self.events):
        if event.type == "run.end":
            return event.data.get("status") or "error"
    return "incomplete"

summary() 再把事件数成几张牌：模型几轮、工具几次、拒绝几次、错误几次、花了多久。排障先看 summary，再下钻到具体 seq。

完整可运行代码：boba/trace.py。测试覆盖编号、JSONL 往返、状态、缺 run.end、summary、文件读写等。在仓库根目录跑：

python3 -m unittest discover -s tests -v
python3 -m boba.trace

5. eval：把录像变成回归测试

trace 解决“这一次发生了什么”；eval 解决“下一次还会不会坏”。

一个 eval case 很简单：固定输入跑一遍，拿到 trace，断言收尾状态等于预期。

@dataclass(frozen=True)
class EvalCase:
    name: str
    expected_status: str
    trace: Trace

def run_eval(cases):
    results = []
    for case in cases:
        actual = case.trace.status()
        results.append(EvalResult(
            name=case.name,
            ok=actual == case.expected_status,
            expected=case.expected_status,
            actual=actual,
        ))
    return results

例如：

EvalCase("正常下单", "ok", ok_trace)
EvalCase("超量被拦", "permission_denied", denied_trace)
EvalCase("预算耗尽", "timeout", timeout_trace)

以后每次改护栏、改预算、改状态，都先跑一遍。没有 eval 的“修好了”，只是你觉得修好了。

6. trace 的四条硬规矩

  1. 只追加，不改写。旧事件被改过，录像就不再是证据。
  2. 一行一件事。不要把整段对话塞进一个模糊的 message；排障时要能按 seq 定位。
  3. 每次运行有 run_id，结束有 run.end。没有收尾就是 incomplete，不要假装成功。
  4. 落盘前脱敏。trace 会保存很久；密码、手机号、支付信息不能原样写进去。

8. 这一课没修的设备

  • 还没接进真正的循环：现在是手动 emit；下一步要在模型轮、工具执行、护栏拒绝、状态写入处自动记录。
  • 日志轮转：trace 会越写越大；需要按天 / 按大小切分，设置保留期。
  • 采样：不是每次运行都要全量落盘；高频场景要采样，但失败运行必须保留。
  • eval 用例太少：现在只有演示 case；需要从真实失败 trace 里沉淀。
  • 脱敏：还没有手机号、地址、支付信息的过滤规则。
  • 并发与归档：留到第 7 课，先把 trace / eval 跑通。
