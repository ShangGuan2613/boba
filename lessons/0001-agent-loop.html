Boba · Lesson 01

一杯奶茶的 Agent 闭环

模型只会“说”，Harness 才会“做”。这一课只做一件事：让模型拿到真实菜单，而不是编一份。

约 12 分钟 · 前置：无 · Harness 地图 · 课程说明

1. 先看一个失败

你开了一家奶茶店，接了一个“智能点单”对话。顾客问：

“今天有什么？”

如果只把这句话丢给模型，它很可能回你：

“今天有珍珠奶茶、芝士莓莓、四季春，都是 15 元。”

句子很顺，但价格是编的——模型没有看过你的菜单。

这不是模型“笨”。它本来就没有菜单、库存、订单这些数据。它只根据上下文生成下一个 token。要让它说真话，得有人把真实数据递到它面前。

2. 模型之外，还缺一层东西

把模型想象成店员：会说话、会判断顾客意图，但不知道今天冰箱里还剩多少珍珠。要让店员真正出杯，你还需要菜单、设备、店规和店长。

这些“模型之外的一切”，就是 Harness。一个常见的说法是：

Agent = Model + Harness

Harness 包括循环、工具、上下文、状态、护栏、预算和可观测性。它不是模型的一部分，而是让模型能安全地作用于世界的那层代码。LangChain 的拆解把这个边界讲得很清楚。

模型负责

  • 理解顾客这句话
  • 决定下一步做什么
  • 生成对顾客的回复

Harness 负责

  • 真的去执行工具
  • 把结果送回模型
  • 限制它能做多过分的事

本课的关键区分：模型输出“我要调用 get_menu”，不等于它真的调用了。它只是生成了一段结构化的请求；执行发生在 Harness 里。

3. 最小闭环，五步

把上面的失败修好，只需要一个循环。点“下一步”，看这杯奶茶怎么从一句话变成真实回答。

顾客提问 “今天有什么？”
模型决定 输出 tool_use
Harness 执行 调用 get_menu()
结果回填 tool_result
模型收尾 生成文本

顾客问：“今天有什么？” 此时模型只有这句话，没有菜单数据。

4. 代码形状

先不接真实模型，也不做花活。最小闭环的骨架只有这些：

messages = [user("今天有什么？")]

while True:
    turn = model(messages)                 # 模型只负责生成
    messages.append(turn.as_message())

    if turn.type == "text":                # 没有工具请求 → 结束
        return turn.text

    result = run_tool(turn.name, turn.args)          # Harness 执行
    messages.append(tool_result(turn.id, result))    # 结果回填

跑起来以后，trace 大概长这样：

seq 1  model.turn   tool_use  get_menu
seq 2  tool.result  {"items": [{"name": "珍珠奶茶", "price": 12}, ...]}
seq 3  model.turn   text      "今天有珍珠奶茶 12 元、芝士莓莓 18 元……"

这段代码还缺很多东西：未知工具怎么办、工具报错怎么办、最多几轮、超时、trace 落盘。它们是后面每一课的主题。

先别急着加抽象。Anthropic 在《Building Effective Agents》里的经验是：成功的实现通常从简单、可组合的模式开始，而不是一上来就套复杂框架。先把这五步跑通，再谈框架。

5. 奶茶店 ↔ Harness

同一个东西，用店里的角色再对一遍。以后卡住时，先问：这是店员的事，还是店长的事？

奶茶店 Harness 里的东西 缺了会怎样
店员 Model 不会对话，也不会决定下一步
菜单 / 配方卡 Tools 只能凭记忆编价格和库存
店长 Agent loop 没人把“点单”推进到“出杯”
小票 Messages / state 第二轮就忘了顾客点了什么
食安红线 Guardrails 10 杯也照做，库存扣成负数
监控 Trace 出错后不知道哪一步坏了

6. 检查理解

先合上上面的内容，凭记忆选。选完才有反馈。

1. 模型说“调用 get_menu”，谁真正执行这个函数？

2. 工具结果为什么必须放回 messages？

3. 哪件事属于 Harness，而不是 Model？

7. 这一课故意没做的事

  • 没有工具参数校验——顾客说“来一杯”，缺哪个参数？
  • 没有未知工具处理——模型编了一个 get_discount 怎么办？
  • 没有预算——模型要是永远调工具，谁喊停？
  • 没有真实模型——先用假模型把闭环跑通，再接 API。

这些都是真实的坑，但一次只挖一个。下一课从你的追问开始。
