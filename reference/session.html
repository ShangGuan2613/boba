一句话

护栏读状态 → 工具改状态 → 模型只看结果

messages 是模型眼前的单子，session state 是柜台后面的订单夹。单笔护栏只看这一张单；session 级护栏看“已有 + 本次”。

订单夹 vs 上下文

messages session state
谁持有 本轮发给模型的消息 Harness / 业务系统
内容 用户、模型、工具结果的对话 桌号、订单、数量、状态
生命周期 可被截断、摘要 跨轮次保留，直到显式删除
模型能否改 能说“我记得” 不能直接改，只能经工具提交
冲突时 参考 权威

def place_order(session, call, tools, guardrails):
    result = run_guarded(
        call, tools, guardrails, session
    )

    if not result.is_error:
        data = result.content["data"]
        session.add_order(
            data["order_id"],
            data["quantity"],
        )

    return result

拒绝或失败不写状态。否则会出现“幽灵订单”：后厨没做，额度却已经被占用。

session 级护栏

class MaxCupsPerSession:
    name = "max_cups_per_session"

    def __init__(self, limit=10):
        self.limit = limit

    def check(self, call, session=None):
        if call.name != "order_create":
            return ALLOW

        if session is None:
            return GuardrailDecision(
                False, "guardrail_error",
                "缺少 session，无法检查总量。",
                "默认拒绝；检查接线。",
            )

        quantity = call.args.get("quantity", 1)
        if session.total_cups + quantity > self.limit:
            return GuardrailDecision(
                False, "permission_denied",
                f"已有 {session.total_cups} 杯，"
                f"再加 {quantity} 杯会超。",
                "不要拆单；转人工。",
            )
        return ALLOW

检查的是 session.total_cups + quantity，不是单独的 quantity。缺少 session 时默认拒绝。

隔离规则

  • 按桌号取夹子：store.get(session_id)，不同桌号不同对象。
  • 只查自己的夹子：order_status 只读当前 session 的订单列表。
  • 跨桌查单一律查无此单：不返回详情，也不确认订单号是否存在。
  • session 缺失默认拒绝：没有桌号，就不知道总量，不能放行。
  • 不要用全局订单表代替 session：全局表适合员工查单，不适合顾客自助查询。

常见 Bug

症状 根因 修复
拆单仍能绕过 只检查单笔 读 session.total_cups
正常单被拒 拒绝/失败也写了状态 只在成功后记账
第二轮忘了点过什么 状态只活在消息里 状态放 Harness，工具读回来
5 号桌看到 3 号桌订单 查询走了全局表 只查当前 session
护栏拿不到总量 没把 session 传进 check 接线时显式传 session；缺失默认拒绝
重启后订单全没了 状态只在内存 落库 / 持久化

术语

术语 含义
session 一段有边界的人机交互；这里用桌号表示。
session state 跨轮次保留的业务状态，比如订单夹。
messages 本轮对话上下文，不等于业务状态。
幽灵订单 被拒绝或失败，却写进了状态的订单。
session 隔离 每个 session 只能读写自己的状态。
三阶段提交 检查 → 执行 → 成功后记账。
