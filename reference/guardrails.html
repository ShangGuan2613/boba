一句话

工具执行之前 → 代码级否决 → permission_denied

预算管“做多少”，护栏管“能不能做”。护栏不是提示词建议，是工具执行前的硬检查；拒绝时工具一次都不执行，但必须回一个 tool_result。

护栏 vs 预算

预算 护栏
管什么 轮数、工具次数、时间 数量、年龄、权限、库存红线
检查点 模型 / 工具动作之前 工具执行之前
拒绝后 收尾 解释规则，循环可继续
错误码 max_turns / max_tool_calls / timeout permission_denied / invalid_quantity
坏了 硬停 默认拒绝

接线位置

def run_guarded(call, tools, guardrails):
    decision = guardrails.check(call)

    if not decision.allowed:
        return denied_result(call, decision)

    return tools.run(call)

只有放行才调用 tools.run。拒绝时工具函数一次都不执行；模型收到 permission_denied，而不是“工具失败”。

护栏检查清单

  • 代码级：不是提示词里的“请不要”。
  • 执行前：工具动手之前检查。
  • 只回答能 / 不能：一条护栏一个判断，不写“尽量”。
  • 拒绝有结果：permission_denied + message + hint。
  • 失败关闭：护栏自己抛异常，默认拒绝。
  • 不可绕过：不自动拆单、不换工具、不假装成功。

本课已知的洞：拆单

单笔限 10 杯，模型拆成两单各 10 杯：两条护栏各自都通过，合计 20 杯。护栏只看自己收到的这一张单，看不到 session 总量。

修法：把已下单总量放进 session 状态，护栏检查“已有 + 本次”；见 Lesson 05 · 状态与 session。

常见 Bug

症状 根因 修复
模型照做超量订单 店规只在提示词里 工具执行前加代码护栏
原料已经用了才拒绝 做完才检查 先过店规，再执行
对话卡死 拒绝时抛异常 回 permission_denied 结果
护栏坏了反而放行 fail open 捕获异常，默认拒绝
拆两单绕过 只看单笔 session 级总量规则

术语

术语 含义
guardrail 工具执行前的代码级否决。
fail closed 护栏自己坏了时默认拒绝，而不是放行。
permission_denied 护栏拒绝的错误码，模型可读、可解释。
拆单 把超量订单拆成多笔，绕过单笔上限。
session 级规则 看整段会话总量，而不是单次调用。
