不变量

1 个 tool_use → 1 个 tool_result

成功是结果，失败也是结果。未知工具、缺参数、工具异常、护栏否决、预算耗尽，都必须回填；不能抛到循环外。每个结果都要带同一个 tool_use_id。

结果形状

成功

{
  "tool_use_id": "call_4",
  "is_error": false,
  "content": {
    "ok": true,
    "data": { ... }
  }
}

失败

{
  "tool_use_id": "call_1",
  "is_error": true,
  "content": {
    "ok": false,
    "error": {
      "code": "missing_argument",
      "message": "...",
      "hint": "..."
    }
  }
}

这是 Harness 内部对象。发给真实 API 时，content 会序列化为字符串或内容块，但 id 配对与 is_error 的语义不变。

错误码

code 触发 模型下一步 不要做
missing_argument 必填参数没给 问顾客缺的那一项 猜默认值硬做
unknown_argument 给了没声明的参数 删掉或改正参数后重发 把多余参数传给工具
unknown_tool 调用了未注册的工具 改用已注册工具，或告知做不到 原样重试
tool_failed 工具内部抛异常 告知稍等，必要时换只读工具 假装成功
permission_denied 护栏否决 解释规则，提供合规替代 绕过护栏
budget_exhausted 轮数 / 调用数 / 时间耗尽 停止并交接 继续试

工具作者检查清单

  • 名字像动作：order_create，不是 order。
  • 参数有边界：必填、类型、枚举值写清楚，缺了就报 missing_argument。
  • 错误可行动：message 说发生了什么，hint 说下一步怎么改。
  • 不抛自定义异常给循环：在工具边界转成结果；trace 由 Harness 记。
  • 只读与写入分开：查询失败可以换只读兜底；下单失败不能假装成功。
  • 结果可序列化：返回 dict / list / 基本类型，不返回对象或异常实例。

常见 Bug

症状 根因 修复
对话突然结束，顾客没收到回复 工具异常逃出循环 工具边界 try/except，回填 tool_failed
模型重复调用同一个不存在的工具 未知工具没有回填结果 registry 返回 unknown_tool
模型把 A 单的结果当成 B 单 tool_use_id 配错 结果必须带原请求的 id
模型在缺参数时编了一个默认值 错误信息没有 hint 明确写“先问顾客，不要猜”
失败被当成成功，订单状态错乱 is_error 忘了设 true 由 content["ok"] 统一推导

术语

术语 含义
tool_use 模型发出的调用请求：工具名 + 参数 + 唯一 id。
tool_result Harness 执行后的回填：结果内容 + 同一个 id + 是否错误。
is_error 告诉模型“这次失败”；不能靠模型猜 content 里的 ok。
工具边界 Harness 调用工具函数的那一层；异常在这里转成结果。
恢复动作 模型收到错误后的选择：问顾客、换工具、停止。
