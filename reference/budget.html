三个闸门

闸门 限制什么 默认值 状态
max_turns 模型调用轮数 8 max_turns
max_tool_calls 工具执行次数 16 max_tool_calls
max_seconds 墙钟时间 60 秒 timeout

硬限制，不是提示词建议。检查放在动作之前：先看额度，再决定做不做。

检查位置

while True:
    budget.start_turn()          # 模型调用前
    turn = model(messages)

    if turn.type == "text":
        return ok(turn.text)

    for call in turn.tool_calls:
        budget.start_tool()      # 工具执行前
        result = registry.run(call)
        messages.append(result)

每个闸门只拦自己的动作：max_turns 只拦模型调用，max_tool_calls 只拦工具执行；max_seconds 两个都拦。工具额度用完后，仍允许一个不带工具的收尾回合。

铃响之后

状态 给顾客 不要做
max_turns “今天先聊到这里……稍后人工同事跟进。” 继续硬聊
max_tool_calls “今天先做到这里，您这杯已经排上……” 假装已经出杯
timeout “现在排队比较久，我先帮您留单……” 让顾客继续干等
ok 正常结果 多问已经答过的

状态给日志，message 给顾客。不要把内部暗号直接甩给顾客。

收尾时的 invariant

如果铃响时手里还有没执行的 tool_use，也要回一张 tool_result，is_error: true，code: budget_exhausted。第 2 课的“每个调用都有结果”不能破。代码里用 budget_error_result(call, status) 生成这张小票。

{"tool_use_id": "call_17", "is_error": true,
 "content": {"ok": false, "error": {
   "code": "budget_exhausted",
   "message": "max_tool_calls 已用完",
   "hint": "停止并交接，不要继续试。"}}}

为什么不能直接 break：直接停会留下悬空的 tool_use；下一次模型调用或恢复会话会看到一个没有结果的请求，真实 API 可能报协议错误，模型只能重复或猜。break 只停住循环，没有关掉单子。

trace 形状

常见 Bug

症状 根因 修复
循环停不下来 只在提示词里写“请尽快” 代码里检查三个预算
总是多花一次工具调用 做完才检查 动手前检查并扣减
顾客收到空白 预算异常逃出循环 捕获并返回 fallback message
tool_use 没有结果 铃响后直接 break 补 budget_exhausted 结果
分不清是时间还是次数 没有 trace / 状态 记录 status 与 used

术语

术语 含义
max_turns 一次 run 里最多调用模型几次。
max_tool_calls 一次 run 里最多执行工具几次。
max_seconds 一次 run 的墙钟上限。
budget_exhausted 铃响时回给待执行工具调用的错误码。
fallback message 铃响后给顾客的说明，不是内部状态原文。
