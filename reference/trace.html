trace 与 eval 速查

一页纸：一行一件事、状态怎么收尾、eval 怎么把录像变成回归。

← Lesson 06 · Lesson 05 · Harness 地图

一句话

trace 记录事实 → eval 回归事实

trace 解决“这一次发生了什么”；eval 解决“下一次还会不会坏”。没有 run.end 的 trace，状态是 incomplete，这本身就是信号。

事件形状

{
  "seq": 3,
  "ts": 1.2,
  "run_id": "run_20261119_001",
  "type": "tool.call",
  "data": {
    "tool": "order_create",
    "quantity": 10
  }
}
字段 作用
seq顺序；排障时按它定位。
ts时间；算耗时、看重试间隔。
run_id把同一次运行的事件串起来。
type事件类型，如 run.start、tool.call、run.end。
data细节；一行只放一个事实的相关字段。

常见事件类型

type 什么时候写
run.start一次运行开始，记录用户输入 / session。
model.turn模型输出一轮（文本或 tool_use）。
tool.call准备执行工具，记录工具名和参数。
tool.result工具返回，记录 is_error 和结果摘要。
guardrail.denied护栏拒绝，记录 code 和原因。
state.write状态成功写入，记录变更摘要。
run.end运行收尾，记录最终 status。

收尾状态

status 含义
ok正常收尾。
permission_denied护栏拒绝；模型可以解释或转人工。
max_turns轮数额度用完。
max_tool_calls工具调用额度用完。
timeout墙钟时间超限。
incomplete没有 run.end：崩溃、重启或漏收尾。
error其他未分类错误。

trace vs eval

trace

  • 一次运行的事件流
  • 只追加，不改写
  • 用来排障、审计、回放
  • 失败运行必须保留

eval

  • 固定用例 + 期望状态
  • 每次改动后重跑
  • 用来防回归
  • 用例来自真实失败 trace

落盘与读取

trace = Trace("run_1")
trace.emit("run.start", user="3 号桌")
trace.emit("run.end", status="ok")

trace.write("traces/run_1.jsonl")
restored = Trace.read("traces/run_1.jsonl")

restored.status()   # "ok"
restored.summary()

JSONL 一行一个 JSON，便于 grep、按 run_id 过滤和原样回放。

常见 Bug

症状 根因 修复
出事后无法复盘 只记最终结果 每个模型轮 / 工具调用 / 拒绝都记事件
事件顺序错乱 并发写、没有 seq 单次运行内串行编号；跨运行用 run_id 区分
状态显示成功 漏写 run.end 或默认 ok 没有 run.end 就是 incomplete
trace 被改过 覆盖写 / 回填旧事件 append-only；修正用新事件
日志泄密 原样落盘手机号、支付信息 落盘前脱敏
修好后又坏 没有 eval 把失败 trace 变成固定 case

术语

术语 含义
trace按顺序记录的事件流。
eventtrace 里的一行，一个事实。
run_id一次运行的唯一标识。
append-only只追加新事件，不改旧事件。
JSONL一行一个 JSON 的文本格式。
eval固定用例 + 期望行为的回归集。
