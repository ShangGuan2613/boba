Harness 地图与术语

一页纸：Agent 里到底有哪些部件，各自对应奶茶店的什么角色，缺了会出什么事。

← Lesson 01 · 课程说明 · 可打印

一句话

Agent = Model + Harness

Harness 是“模型之外的一切”：循环、工具、上下文、状态、护栏、预算、观测。模型负责生成，Harness 负责让生成作用于世界，并在出格时喊停。

八个部件

部件 干什么 奶茶店对应 缺了会怎样
Loop 反复“模型 → 工具 → 模型”，直到文本收尾或预算耗尽 店长把点单推进到出杯 模型只说不动，或者一次工具后停住
Model adapter 把内部消息格式翻译成模型 API，再把响应翻译回来 店员听的方言 换模型就要重写业务代码
Tools 可执行的函数：查菜单、查库存、建订单、提交 菜单、冰箱、收银机 只能凭记忆编价格和库存
Context 这一轮模型能看见的消息、系统提示、工具结果 店员眼前的单子 信息太多淹没重点，或太少无法决策
State / Session 跨轮保存购物车、订单号、顾客身份 小票和订单夹 第二轮就忘了顾客点了什么
Guardrails 代码级否决：超量、越权、危险操作 食安红线和店规 10 杯也照做，库存扣成负数
Budgets 限制轮数、工具调用次数、墙钟时间 排队时长和原料上限 模型死循环，账单和顾客一起爆炸
Trace / Evals 记录每一步事件；用固定用例回归 监控和复盘 出错后不知道哪一步坏了，也没法证明修好了

最小闭环 vs 工程化

最小闭环（第 1 课）

  • 一个 while 循环
  • 一个工具
  • 消息数组
  • 文本即结束

工程化 Harness（后续）

  • 未知工具 / 工具报错收敛
  • 预算与超时
  • 护栏否决也回填 tool_result
  • trace 落盘 + 可回归的 eval

顺序不能反。先让五步跑通，再逐个补失败模式；每补一个部件，都要能说出它挡住了哪个具体事故。

术语表

术语 含义
turn 模型的一次输出。可能是一段文本，也可能是一个或多个工具请求。
tool_use 模型发出的结构化调用请求：工具名 + 参数 + 唯一 id。它不是执行结果。
tool_result Harness 执行后回填的结果，必须用 tool_use_id 与请求配对。
messages 这一轮对话的上下文。工具结果不回填，下一轮模型就看不见。
harness 模型之外的运行层：循环、工具、上下文、状态、护栏、预算、观测。
guardrail 代码级否决，不是提示词建议。被否决也要给模型一个结果。
budget 对轮数、工具调用次数、时间的硬上限。
trace 按顺序记录的事件流，用来复盘一次运行到底发生了什么。
eval 固定输入 + 期望行为的回归集，用来证明改动没有让旧能力退化。

课程路线

  1. 01 · 一杯奶茶的 Agent 闭环：模型 → 工具 → 模型。
  2. 02 · 工具协议：参数、错误、未知工具。
  3. 03 · 预算：轮数、调用次数、超时。
  4. 04 · 护栏：代码级否决与库存红线。
  5. 05 · 状态与 session：小票不能丢。
  6. 06 · trace 与 eval：出错能复盘，改动能回归。
